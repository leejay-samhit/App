# Android release optimisation (R8 / DEX) — audit + change record

**Play Console before this change**

| Metric | Value |
|---|---|
| DEX code optimisation | Low |
| Uncompressed DEX | 29.5 MB |
| Obfuscation | 1% |
| Optimisation / shrinking | not shown |
| 16 KB page size | supported |

## Phase 1 — Audit

**Framework.** Expo SDK 54 (`expo ~54.0.35`) + React Native 0.81.5, New
Architecture, Hermes, expo-router. Managed workflow: there is **no checked-in
native project** — `/app/frontend/android` contains only `keystores/`
(`networkrupay-release.jks`). The `android/` project is generated by
`expo prebuild` inside the Emergent build pipeline on every build, so Gradle
and AGP versions are the ones Expo SDK 54 pins (**AGP 8.x / Gradle 8.x**), not
values this repo sets.

**How the AAB is produced.** Publish → Android build in Emergent. It runs
prebuild + `gradlew bundleRelease` with the keystore above. There is no Gradle,
JDK or Android SDK in this container (`java`, `gradle`, `sdkmanager` all
absent, `ANDROID_HOME` empty), so a build cannot be produced or inspected here.

**ROOT CAUSE of "Obfuscation 1%".** `app.json` →
`plugins → expo-build-properties → android` had:

```json
"enableProguardInReleaseBuilds": false,
"enableShrinkResourcesInReleaseBuilds": false
```

With ProGuard/R8 off, Gradle runs **D8 only**: the bundle is dexed but never
shrunk, optimised or obfuscated. The 1% Play reports is the handful of library
classes that ship pre-obfuscated; the optimisation and shrinking percentages
are blank because **no `mapping.txt` was produced at all** — Play has nothing to
measure. 29.5 MB of DEX is the full un-shrunk React Native + Expo + AndroidX
surface.

**Existing rules.** 8 keep lines (React, Hermes, JNI, fbreact specs,
reanimated, worklets, expo.modules, versioned host). Correct as far as they
went, but never exercised because R8 never ran.

**SDKs that must survive R8** (all reflection surfaces): React Native
bridge/TurboModules, Expo modules (resolved by package name), Hermes,
Reanimated + Worklets, Gesture Handler, Screens, SVG, **react-native-webview —
this is where Razorpay checkout runs**, Firebase/GMS (push via
`google-services.json`), androidx.biometric (local auth), androidx.security
(secure store), androidx.camera, OkHttp/Okio, Kotlin metadata, Parcelable.

## Phase 2 — What changed

| File | Change |
|---|---|
| `frontend/app.json` | `enableProguardInReleaseBuilds: true`, `enableShrinkResourcesInReleaseBuilds: true`, and `extraProguardRules` expanded from 8 to **64** reviewed rules |
| `frontend/android/proguard-rules.pro` | **new** — the same 64 rules, documented line by line. This is the file to review/edit; the `app.json` string is generated from it |

Deliberately **not** done:

* **No AGP 9.0.** Expo SDK 54 / RN 0.81 pin AGP 8.x; forcing AGP 9 breaks
  prebuild and every Expo module. Play's banner is advisory — R8 on AGP 8
  already satisfies the DEX-optimisation signal. Revisit when Expo ships an
  SDK that supports AGP 9.
* No `minifyEnabled` hand-edits — the generated project would overwrite them.
* No change to applicationId (`com.slangcart.app`), signing, permissions,
  `buildArchs`, JS, APIs or business logic.
* R8 **full mode** is already the AGP 8 default; no extra flag needed.

A conservative `-optimizations !method/inlining/*` is included so the WebView
→ JS payment callbacks are never inlined away.

## Phase 3 — Regression testing

JS/TS is untouched by this change, so the backend and in-app behaviour cannot
regress from it; the preview still boots clean after the config change. What
R8 *can* break is native module resolution, and that only appears in a release
build on a device. **The checklist below must be run on the new AAB**
(install the `.aab`-derived APKs or the Play internal-test track):

launch · login + OTP · Google sign-in · customer and vendor accounts ·
browsing and search · cart → checkout → orders · **Razorpay payment (WebView)**
· mobile + DTH recharge · wallet, cashback, refunds · **push notifications** ·
biometric login · camera/photo upload · location · admin screens.

If a screen renders blank or a native module is "undefined" in the release
build, it is a missing keep rule — add it to `android/proguard-rules.pro`,
regenerate the `app.json` string and rebuild. Nothing else needs to change.

## Phase 4 — Release validation (must be done in the build pipeline)

1. **Publish → Android build** in Emergent. The existing keystore and
   applicationId are reused automatically.
2. Confirm R8 actually ran: the build log shows an `:app:minifyReleaseWithR8`
   task, and the artefact bundle contains
   `app/build/outputs/mapping/release/mapping.txt`. **No mapping.txt = R8 did
   not run** — do not upload and report the log instead.
3. **Keep `mapping.txt` for that exact build.** It only matches that one
   build; a later rebuild produces a different mapping.
4. Compare: Play Console → App bundle explorer → the new version's DEX size
   against 29.5 MB. Expect a materially smaller DEX and obfuscation well above
   1%; shrinking/optimisation percentages appear once a mapping exists.
5. **Uploading the mapping:** Play Console → the app → Release → App bundle
   explorer → pick the new version → **Downloads** tab → "ReTrace mapping
   file" → upload `mapping.txt`. (Builds made with Play App Signing usually
   carry it automatically; upload only if the slot is empty.)
6. Nothing is published automatically — the AAB has to be promoted by hand.

## Honest limitation

This container has no Android toolchain, so the AAB, its DEX size and its
mapping file **cannot be produced or verified here**. What is verified: the
Expo config now resolves with ProGuard/R8 and resource shrinking enabled
(`npx expo config --type public`), `app.json` is valid JSON, the rule set
covers every reflection surface in this app, and the preview still runs. The
measured before/after DEX numbers can only come from the next Android build.
